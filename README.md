# 古建木结构 · 离线测绘台

三组测绘队轮流进现场、断网各自作业的榫卯构件测绘前端：**本地草稿可接续、回站先合并差异、确认完才更新建筑关系、关系失效需审核、上传按原批次断点重试**。

## 解决的现场问题

| 痛点 | 机制 |
| --- | --- |
| 断网时各组各改各的，回站上传把别人刚定的榫卯冲掉 | 断网瞬间冻结站端快照；恢复后**三路合并**（基线 / 本地 / 站端），单方修改自动取值，双方同改列为**冲突逐项选择**，字段与关系两阶段都确认完才更新建筑关系 |
| 构件被其他构件引用，停用/替换后关系悬空 | 停用或替换立即让引用边失效重算，关系图虚线标注并**高亮受影响节点**（两端及一度牵连），生成审核单；端点未恢复在用前不允许恢复，审核通过才按当前榫卯类型恢复，驳回则归档 |
| 上传失败后整批重传、重复写入 | 批次带游标与"最后确认构件"；重试**从断点继续**，测量以草稿 id 为幂等键，已写入绝不重复 |
| 老版本草稿没有批次号 | 启动时按**最后编辑时间**补一版批次号（`B-补版-YYYYMMDD`），原记录完整留档，履历可查 |
| 刷新/关页面丢草稿 | 全部状态持久化到 localStorage，未决合并、失败批次断点均保留 |

## 功能页签

- **现场测量**：构件编号、木材、榫卯类型、截面尺寸、病害位置、变形、修缮建议；在线直接入库，离线进批次草稿；可挂停用/替换提案
- **构件清单**：榫卯类型筛选、待审受影响节点过滤、在线停用/替换
- **尺寸记录表**：本地草稿 / 站端入库分视图，标注批次与状态
- **病害标记图**：大雄宝殿剖面示意图，按病害类型着色，点选看详情
- **关系视图**：柱—斗拱—梁—檩榫卯图，失效边红色虚线 + 受影响节点高亮
- **同步中心**：网络切换、断网演练（模拟别组回站抢改）、失败点注入、差异审核、批次续传、关系审核
- **履历留档**：测量、合并、关系、审核、补版、批次、别队提交全履历，可展开原记录快照

## 建议演练流程

1. 顶栏切到「甲组」→ 点「在线」**断网**（自动冻结基线）
2. 现场测量录 2~3 条草稿（给 C-03 勾"停用"）
3. 同步中心点「别组改 A-03 榫卯」「别组补 P-11 病害」制造站端变化
4. **恢复联网 → ① 开始合并**：逐项处理字段冲突 → 再处理榫卯关系冲突 → ③ 更新建筑关系
5. 看关系视图：R-03 虚线失效、受影响节点高亮，同步中心出现审核单
6. 挂失败点（如第 2 条）→ ② 按批次上传 → 失败后**原批次重试**，尺寸记录表里无重复入库
7. 履历留档里看初始老草稿的补版记录，展开可见无批次号原记录

## 技术栈与目录

React 19 + Vite + TypeScript，零后端（localStorage 持久化 + 内置站端模拟）。

```
src/
  types.ts            领域模型
  data/seed.ts        大雄宝殿 8 构件 / 5 关系 / 1 条无批次老草稿
  logic/engine.ts     纯逻辑：三路差异、本地关系视图、失效重算、受影响节点
  store.tsx           reducer：草稿/批次/合并/审核/断点续传/持久化/老稿补版
  components/         测量表单、清单、尺寸表、病害图、关系图、同步中心、履历
scripts/
  check-logic.ts      纯函数断言
  check-flow.ts       reducer 全链路断言（47 项）
```
